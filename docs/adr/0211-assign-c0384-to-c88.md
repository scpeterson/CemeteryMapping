# ADR 0211: Assign C-0384 to C-88 without moving geometry

Status: Accepted
Date: 2026-11-14

The owner requests assigning Allan Watenpool's C-0384 to C-88 while preserving its estimated polygon and observed TLC-HS-0384 marker. The imported registry lists “Allan Watenpool”, lot “88”, with “Endowed by Margaret Watenpool”. Nearby Margaret and Byron gravesites already have C-88 assignments. A read-only DEV check on November 14 confirmed C-0384 still had neither lot field populated and the matching active C-88 exists in the same cemetery and Section C.

Migration 518 changes only C-0384's `lot_uuid`, `lot_id`, and `updated_at`. The registry-backed relationship does not assert schematic containment or surveyed burial boundaries. It does not change polygon or marker geometry, geometry metadata, identifiers, burial facts, marker links, source evidence, lot geometry, or ownership events. Assignment can expose existing lot-level ownership through normal application inheritance; this migration creates no deed or ownership history.

Databases without active C-0384 skip the change. Existing correct C-88 assignments are preserved without a repeated timestamp update. Reject duplicate active C-0384 records, unexpected identity/hierarchy, missing or mismatched target lot, non-burial status, conflicting or partial assignments, and missing active marker/link evidence. Existing lot-capacity enforcement remains in effect. A different assignment requires review, not overwrite.

The C-0383/C-0384 overlap, C-0384/C-0385 spacing, the marker's position south of schematic C-88, and other surrounding geometry issues remain separate reviews. No earlier geometry migration or checksum is changed. See [ADR 0108](0108-c0383-alignment-c0425-retirement.md) for the prior C-0383 correction and retained overlap; its dated measurements are not new survey results.

Transactional database regressions verify both assignment fields, byte-for-byte preservation of all other sampled records and geometry (except the target update timestamp), marker/source/face data and links, neighboring records, safe repeated execution, absent/retired source behavior, prerequisite failures without partial changes, and the production capacity trigger. Run `APP_ENV=test node --test scripts/c0384-lot-assignment.integration.mjs`, `npm run lint`, and the normal server/database checks. Fresh/demo databases without the source record must migrate successfully.

This PR prepares the change; it does not establish application to DEV, hosted TEST, STAGE, or PROD. Rehearse against a copy before applying, retain a backup, and verify unchanged geometry/marker plus both C-88 relationship fields. Automatic rollback is empty to preserve subsequent assignment/ownership edits; use a reviewed forward correction if evidence changes.
